# Pendientes que dependen del backend

Todo lo de esta lista quedó fuera del port porque en el producto original depende de Fortify o de `@laravel/passkeys`, o
porque hoy lo resuelve el servidor. Las URL se conservaron para que el backend nuevo encaje sin cambios.

## Pantallas y funciones que no se portaron

| Qué                                                                                                     | Origen                                                                | Por qué falta                                           |
| ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------- |
| Desafío de doble factor (`/two-factor-challenge`)                                                       | `pages/auth/two-factor-challenge.tsx`                                 | 2FA (Fortify)                                           |
| Seguridad de la cuenta (`/settings/security`)                                                           | `pages/settings/security.tsx`                                         | cambio de contraseña, 2FA y passkeys                    |
| Passkeys: registro, listado, verificación, bloque «iniciar con passkey» en `login` y `confirm-password` | `components/passkey-*.tsx`, `manage-passkeys.tsx`                     | `@laravel/passkeys`                                     |
| Doble factor: configuración, códigos de recuperación                                                    | `manage-two-factor.tsx`, `two-factor-*.tsx`, `use-two-factor-auth.ts` | Fortify                                                 |
| Borrar cuenta                                                                                           | `components/delete-user.tsx`                                          | Fortify                                                 |
| Reenvío de verificación desde el perfil, con el aviso «sin verificar»                                   | `pages/settings/profile.tsx`                                          | el usuario simulado siempre está verificado             |
| Avisos de servidor (`flash`) y el componente `sonner`                                                   | `use-flash-toast.ts`, `ui/sonner.tsx`                                 | los emitía el servidor; ningún flujo actual los dispara |

El menú de ajustes del marco muestra solo «Perfil» y «Apariencia»; «Seguridad» vuelve cuando exista la pantalla.

## Lo que hoy es simulado y el backend debe resolver

| Tema                           | Hoy en este proyecto                                                                                                                                                                       | Qué debe hacer el backend                                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sesión                         | no hay; `getUser()` siempre devuelve el usuario de demostración                                                                                                                            | autenticación, cierre de sesión (hoy solo lleva a `/login`) y redirección a `/login` sin sesión                                                                  |
| Envíos de acceso y perfil      | `MockForm` con errores simulados (solo `test@example.com` / `password` entra)                                                                                                              | validación y mensajes de error localizados (el texto «Estas credenciales no coinciden…» sale de `lang/es/auth.php` en el origen; aquí es la clave `auth.failed`) |
| Escenario de demostración      | `localStorage` (`arx-demo-sector`)                                                                                                                                                         | `DemoScenarioController` con sesión; solo existe con `ARXNET_DEMO_DATA=true`                                                                                     |
| Idioma                         | `localStorage` (`locale`)                                                                                                                                                                  | idioma por usuario o sesión (`LocaleController`)                                                                                                                 |
| Apariencia                     | `localStorage`                                                                                                                                                                             | cookies leídas por el servidor para pintar `<html>` sin script (hoy lo hace el script de `index.html`)                                                           |
| Datos del mapa y departamentos | `DataSource` mock                                                                                                                                                                          | implementación `http` de `DataSource` con las mismas formas (`src/data/contracts`)                                                                               |
| Nombres localizados            | los puntos de referencia se traducen en el cliente (`map.landmark.*`); organización, zonas y departamentos solo están en español en los fixtures                                           | localizar en el servidor                                                                                                                                         |
| Contrato                       | copia de `types/generated/index.ts` (commit `8ea5fff` del origen)                                                                                                                          | regenerar desde los DTO PHP y recopiar cuando cambien                                                                                                            |
| Respuesta 404                  | página `NotFound` de la interfaz                                                                                                                                                           | respuesta HTTP 404 real para un departamento inexistente                                                                                                         |
| Organización y sede            | solo presentación                                                                                                                                                                          | tenancy y permisos (fases 2 y 3 del origen)                                                                                                                      |
| Centro de control (Fase 3.0)   | `src/features/campus/control-center/demo-data.ts`: indicadores por departamento, «Atención ahora», solicitudes/órdenes/recepciones, caja y frescura, todo rotulado «Datos de demostración» | contrato y endpoints para avisos, estado por departamento y proceso de compra; la revisión de solicitudes hoy solo muestra un aviso de prototipo                 |
